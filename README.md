# InteractionOCSVM

## Description
**InteractionOCSVM** is a new approach for the selection of relevant docking poses in high-throughput virtual screening. A docking pose is classified as relevant or non-relevant based on the similarity between its predicted binding mode and an ensemble of reference binding modes. The classification is performed by a **O**ne **C**class **S**upport **V**ector **M**achine model (OCSVM), trained on binding data from a molecular dynamics simulation of a single known ligand bound to the target protein.

This approach has been tested retrospectively on a panel of diverse G-protein coupled receptors (GPCRs), leading to an increase in enrichment compared to simple docking, and to the intorduction of an efficacy bias between the selected active molecules.

The method was built to handle binding information in the form of binary Interaction FingerPrints (IFP), or as pseudo-3D Interaction Graphs (IG), generated by the software suite **IChem**. While other interaction representation (different types of IFP) could be used in the same framework, they are not currently supported in this release.

## Requirements
1. A working installation of IChem 5.2.9 or IChem 5.2.8
2. A conda environemnt containing all of the necessary installed modules (see Installation)

## Installation
**conda** is required to install InteractionOCSVM. If *conda* is not already installed on your machine, or you are unfamiliar with its use, a user guide can be found [here](https://docs.conda.io/projects/conda/en/latest/user-guide/getting-started.html).

1. Clone the InteractionOCSVM repository and enter the directory.
```console
git clone https://github.com/LIT-CCM-lab/InteractionOCSVM
cd InteractionOCSVM
```
2. Create the conda environment from the *litaf_env.yaml* file.
```console
conda env create -f  interactionocsvm_env.yaml
conda activate InteractionOCSVM
```
3. Install the Python modules in the InteractionOCSVM repository
```console
pip install interocsvm/ mol2df/ pyichem/
```

## Apptainer

To facilitate the use of InteractionOCSVM this repository includes an [Apptainer](https://apptainer.org/) definition file, which has been tested as compatible with the developed code.

To create the Apptainer image run the command below.

```console
apptainer build InteractionOCSVM.sif InteractionOCSVM.def
```

Afterwards you can use the container to run LIT-AlphaFold, without the need to setup the environement.

```console
apptainer run InteractionOCSVM.sif bin/script.py
```

## How to use

The InteractionOCSVM process is split in four main steps:
- Data preparation
- Model training
- Docking data preparation
- Docking pose evalaution

This part gives basic information on how to use this method, for more details please visit the project's Wiki.

### Data preparation
In the current version InteractionOCSVM uses data from molcular dynamics simulation for its training. To obtain the relevant interactions it is necessary to convert the trajectory into pairs of *.mol2* files, in order to process them with *IChem*
```console
python bin/trajectory_converter.py \
-top topology_file.ext \
-traj trajectory_file_1.ext trajectory_file_2.ext \
-r "AMBER MASK selecting the receptor" \
-l "AMBER MASK selecting the ligand" \
-ref reference_file.pdb \
-a "AMBER MASK for structure alignment" \
-ln "Name of the ligand" \
-rn "Name of the receptor"
```
In this way the frames will be converted into *.mol2* files with the receptor saved in the folder *ichem_outputs/strucrues/receptor*, and the ligand in the folder *ichem_outputs/strucrues/ligand*.

The current implementation of the scripts accepts only topologies with atom types from the **AMBER** or **CHARMM** force fields. Some atom types of the aforementioned force field might not have been implemented in the current version of the script. In case of missing atom or bond types please follow the instructions in the Wiki.

After conversion interactions are detected using IChem
```console
python bin/compute_interactions.py -ic absolute/path/to/IChem
```
The information regarding the outputs will be saved in the files: *ifp.pkl*, *ints_hyd.pkl*, *ints_newhyd.pkl*

### Model training
Once the data from the MD simulation is gathered it is possible to train the OCSVM models using the detected interactions.
Currently two different training methods have been implemented, one for IFP and one for IG.

For IFP training the *trainer_ifp.py* script is used
```console
python bin/trainer_ifp.py \
-f ifp_1.pkl ifp_2.pkl \
-n "base_name_for_the_models"
```

For IG training the *trainer_ig.py* script is used
```console
python bin/trainer_ig.py \
-f ints_hyd_1.pkl ints_hyd_2.pkl \
-n "base_name_for_the_models"
```
The trainers present a graphical interface to facilitate model training.
The OCSVM models will be saved as *.pkl* files.

### Docking data preparation
Docking can be performed with any tool, however to proceed to interaction detection it is important that both the receptor and the ligand files are saved in *.mol2* format with SYBYL atom types.

With the current script ligand files and receptor files should be stored in two separate folders, and files corresponding to the same ligand-receptor files should have the same name, or start with the same name (es lig_1234.mol2 and lig_1234_protein.mol2). To facilitate calculations it is advised to store the files in two folders named *ichem_outputs/structures/receptor*, and *ichem_outputs/structures/ligand*.

Once the poses are prepared protein ligand interactions can be detected using IChem
```console
python bin/compute_interactions.py -ic absolute/path/to/IChem
```

### Docking pose evalaution
The docking poses are rescored based on their binding mode using the OCSVM models.

For IFP interactions
```console
python bin/scoring_ifp.py \
-c ifp_classifier_1.pkl ifp_classifier_2.pkl\
-f ifp_1.pkl ifp_2.pkl
```
For IG interactions
```console
python bin/scoring_ig.py \
-c ig_classifier_1.pkl ig_classifier_2.pkl\
-f ints_hyd_1.pkl ints_hyd_2.pkl
```
Each set of binding modes is evalauted separately by all the OCSVM models passed to the script, and the results are saved as *.csv* files. A positive score indicates that the binding mode in the docking poses is comparable to the references, while a negative score indicates that the binding mode is significantly different from the references.
